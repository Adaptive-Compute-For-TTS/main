# SQLite run storage

The default database is `backend/data/app.db`, configurable through `ADAPTIVE_TTS_DATABASE_URL`. SQLAlchemy defines one application table, `runs`, in `backend/app/models.py`. Each submitted request creates one row; the worker updates that same row throughout its lifecycle.

| Column | Declared type | Nullable | Meaning |
| --- | --- | --- | --- |
| `id` | `VARCHAR(36)` | No | UUID generated by the application; primary key and queue job identifier. |
| `prompt` | `TEXT` | No | User's input text. Database requires nonblank trimmed text; API also trims it and limits it to 5,000 characters. |
| `nfe` | `INTEGER` | No | Fixed compute budget. Database and API allow integers 4–32; frontend offers 4, 20, 32. |
| `status` | `VARCHAR(9)` | No | `queued`, `running`, `completed`, or `failed`. Indexed as `ix_runs_status`. |
| `created_at` | `DATETIME` | No | UTC creation time. |
| `updated_at` | `DATETIME` | No | UTC time of the most recent ORM update. |
| `started_at` | `DATETIME` | Yes | Set when a worker claims a queued run. |
| `completed_at` | `DATETIME` | Yes | Set on completion or failure. |
| `result` | `JSON` | Yes | Worker result and metrics, populated on success. SQLite stores serialized JSON rather than separate metric columns. |
| `audio_path` | `VARCHAR(1000)` | Yes | Filesystem path to the validated WAV, not audio bytes. |
| `error_message` | `TEXT` | Yes | Failure reason; no fabricated successful result is stored on failure. |

UUIDs, initial status and timestamps are application defaults, not SQL `DEFAULT` clauses. SQLite drops timezone metadata; the API serializes stored timestamps as UTC. SQLite's declared string lengths do not themselves enforce a length limit.

## Result format

`result` is an extensible object returned by the worker. Current real generation includes audio duration (`audio_s`), generation duration (`time_s`), real-time factor (`rtf`), sample rate, peak GPU memory (`peak_vram_mb`), per-patch NFEs (`nfe_per_patch`), validation results and execution settings. New FastAPI worker runs populate `telemetry` with fingerprint, timing, memory, GPU samples and errors, and `quality` with WER/CER, transcript, optional reference-speaker similarity, scorer metadata and errors. CPU runs report NVIDIA-only measurements as unavailable. Historical records may still have null diagnostics. The frontend retains the entire result object and renders dedicated validation, telemetry and quality sections.

Validation failures preserve their measurements in `result` with a failed run status and no playable audio path. Optional telemetry/scoring failures are reported inside their result objects and do not discard a successfully validated WAV. No schema migration is required.

There is no database column for percentage, current denoising step, queue position, or intermediate telemetry. Current progress means the run's lifecycle status. The frontend polls active run records every two seconds; the current API does not expose SSE. `audio_url` is computed by the API from a completed run's ID/audio path and is not a database column.

## Queue and files

`POST /runs` commits the queued row, then adds its UUID to an in-process Python `queue.Queue`. The queue is not a SQLite table. The consumer and API share one process. On restart, queued records refill the queue; interrupted running records become failed. Workers change the same record to running, then completed or failed.

Original WAVs live beneath `backend/data/audio` by default. The browser separately persists this device's run metadata in localStorage and completed WAV blobs in IndexedDB. Removing a run from the browser leaves the backend record and original WAV in place. Browser copies are scoped to the exact origin, including the port; clearing site data removes them.

## Read-only inspection

```sh
sqlite3 backend/data/app.db '.schema runs'
sqlite3 -header -column backend/data/app.db \
  'SELECT id, nfe, status, created_at, started_at, completed_at FROM runs ORDER BY created_at DESC;'
```

No schema migration is needed for the runs table UI or browser-side audio persistence.
